## Engineer-Vorschlag

**Option 1 (Folio Post-Borda) — Recommended:** Score-Malus in
`readCouncilTop` nach Borda-Read in Folio.

```ts
function distanceWeight(km: number | null): number {
  if (km == null) return 1.0;       // unbekannt → neutral
  if (km <= 15) return 1.0;         // im 'Pendel-Radius'
  if (km <= 30) return 0.92;        // -8% (User-Radius noch wohl)
  if (km <= 50) return 0.78;        // -22% (am Rand des Such-Radius)
  return 0.55;                       // sehr fern
}
const adjusted = borda_score * distanceWeight(distance_km);
```

Schwellen orientieren sich am `region: "Faro + 50km"` aus
user_context.yaml (statt fixe 20/50/100km).

- **Vorteil:** Council-Repo unangetastet, Fix-Latenz < 15 min, ETA-
  Logik aus 2.7c-Hotfix kann distance-Daten gleich mit-rendern.
- **Nachteil:** „Echter" Borda-Score in `consolidated_top10` bleibt
  unverändert — Folio rendert eine adjustierte Sortierung. Council-
  Worker-Internal-Logs zeigen weiterhin „rohes" Borda.

**Option 2 (Council Vor-Borda) — Sauberer aber Council-Touch:**
Distance als Persona-Prompt-Kontext für Ortskundige +
Distance-Multiplikator in `council_borda.py:113–120`.

```python
distance_weight = 1.0
if object.distance_km and object.distance_km > 30:
    distance_weight = 0.85 if object.distance_km <= 50 else 0.6
weighted = base_score * confidence * distance_weight
```

- **Vorteil:** Score-Transparenz, eine source of truth.
- **Nachteil:** Council-Repo-Edit. Plus Ortskundige braucht
  Distance-km im Prompt-Kontext (bisher nur Adress-Text), sonst
  bewertet sie noch frei.
