## 2. `corrections` (folio.db) — Spam-Recognition-Signal

**20 Einträge, alle von `folio-detail-panel`, Zeitraum 6.–8. Juni
2026.** Alles echte User-Klicks, kein Test-Spam.

Verteilung `(corrected_domain, corrected_actionability)`:
- **16× `immo / archive-silent`** ← Spam-Korrektur (User sah „Immo"-
  Mail die er manuell zu Stumm gezogen hat)
- 2× `system / archive-silent`
- 1× `immo / actionable`
- 1× `system / actionable`

**Beispiele:**
- `feedback_id=638` (2026-06-08T05:24Z) — immo → archive-silent
- `feedback_id=590` (2026-06-08T05:04Z) — immo → archive-silent

**Substanz:** Direktes Spam-Lernsignal. Diese 16 Mails sind „als immo
klassifiziert aber User sagt Spam" — wertvoll für künftiges Marker-
Fine-Tuning (E4-Befund). Beim feedback.db-Reset gehen die zugehörigen
raw bodies verloren, aber die **corrections selbst** (in folio.db)
können erhalten bleiben — `feedback_id` ist Cross-DB-FK ohne harten
Constraint.

## 3. `mail_actionability_override` (folio.db) — User-Übernommen-Signal

**18 raw rows append-only, 4 distinct feedback_ids latest.** Alle 4
latest = `uebernommen`.

Multi-row pro feedback_id zeigt 2.7-Phase-Test-Iteration (gleicher
User klickt mehrfach übernommen → archive-silent → übernommen).

**Beispiele:**
- `feedback_id=638`, latest uebernommen 2026-06-08 05:24
- `feedback_id=590`, latest uebernommen 2026-06-08 05:04
- `feedback_id=589`, latest uebernommen 2026-06-08 05:04

**Substanz:** Schwacher Signal-Wert: die 4 Mails sind unique
„User wollte das ins Council schieben". Aber **die Council-Objects
existieren bereits** in `objects` (über `from_feedback_ids`-Bridge)
— das eigentliche Signal lebt jetzt in `object_status_override`
(siehe #1). Falls feedback.db cleaned wird, gehen diese rows zu
toten feedback_ids — semantisch verloren.

## 4. `hauskauf_workflow` (folio.db) — Reine Test-Substanz aus 2.7c

**14 Einträge, alle `created_by_user_id=1` (default user), Single-
Session 2026-06-08 05:37 → 18:42** (~13h, vom 2.7c-Implementations-
Test).

- 11 erledigt, 2 in_arbeit, 1 offen
- Status-Verteilung deutet auf bewusstes Durchklicken aller Status-
  Übergänge zum Testen.

**Substanz:** **Reine Test-Substanz.** Eine einzige Test-Card
(`council_object_id='<obj-id>'` literal-String, kein echtes
Object-ID) plus eine echte mit Status-Wechseln. **Empfehlung
für Cleanup: mit TRUNCATE** — kein Lern-Signal, würde Frau-Test-
Sicht mit Phantom-Cards starten.
